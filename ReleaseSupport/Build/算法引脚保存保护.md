# 算法引脚保存保护

框架实际读取的固定输出为 `Result_Cam`（OK/NG 及结果码）和 `resultSend`（显示及副相机传递到主相机的汇总字符串），大小写固定。`Global.Result_Send` 是程序内部 PLC 发送字节缓冲区，不是 VPP 输出引脚。

框架按位置给前两个输入赋值：第 0 个输入为图像，第 1 个输入为数据字符串。保存时检查这两个输入位置及声明类型；已有算法还保护它们原先的名称与顺序。`Result_Cam` 支持字符串或整数声明，`resultSend` 支持字符串声明；兼容原有 Object 声明。未运行时的空值不会被当成错误。

主相机额外检查当前配置中 Required 的 VPP 输出；S7 检查 Result_X / Result_Y / Result_A；Profinet 检查相应通道配置的 VPP 输出。副相机不套用主相机的 PLC 输出表。

编辑器使用独立草稿，未保存或校验失败的修改不会进入运行缓存。上方 Save 校验通过后，先准备各关联通道的独立算法副本，再以临时文件原子替换保存文件，最后更新缓存。通道正忙、相机恢复中或在线状态切换中时，阻止此次保存；不会主动连接设备或发送 PLC 信号。

内嵌 VisionPro 原生保存/另存为入口收起，使用上方 Save。Ctrl+S 走相同保存路径，Ctrl+Shift+S 提示使用上方 Save。其它外部软件直接编辑磁盘 VPP 不受本应用保护。

校验失败时弹窗及日志列出具体引脚，不自动补引脚，以免产生无连接的假接口。请恢复引脚及其实际连接后重新保存。新建的空白 Inspection.vpp 也要配置好接口后才能保存为有效算法。

验证使用空白 ToolBlock 和隔离临时文件：缺失/改名/类型错误、文件不覆盖、草稿与缓存隔离、实际保存路径、主副缓存更新和忙通道保护均通过；未 Run 算法，未取图，未连接 PLC。当前真实复杂 VPP 因缺少 PMAlign 功能授权未能完成反序列化，未宣称已通过生产检测验证。
