# 现场诊断记录

当前 V2 适配了 V3 的独立诊断、异常报告及导出功能。程序入口在 VisionPro 检查前启用，设计器/单独构造窗体不会自动启用。`--organize-project` 仍只整理文件，不启动诊断或设备。

## 使用

Help → Export diagnostics（帮助 → 导出诊断包），导出完成提示 ZIP 路径。导出只读文件、复制配置并计算文件身份，不触发相机或 PLC，不查询设备。无需联网。

默认目录为 EXE 旁 `Logs/Diagnostics`，不可写时依次回退到当前用户 `%LOCALAPPDATA%/Aron/Logs/Diagnostics` 和系统临时目录下 `Aron/Logs/Diagnostics`。普通应用日志和 VisionPro 日志保留自己的路径规则。

- `events_*.jsonl`：UTC 时间、递增序号、Session、Build、线程、Operation、级别、来源和消息。事件序号在并发产生时分配，文件行可能交错。
- `Crash/crash_*.txt`：可捕获的异常堆栈、内部异常、最近 200 条事件、最后观察节点。
- `Packages/AronDiagnostics_*.zip`：导出的诊断资料，不自动上传，也不自动清理。

关键节点覆盖启动/VPP 反序列化、通讯输入、触发等待通道锁、相机取像、ToolBlock.Run 前后、输出读取及结果写入前后。每次检测及子相机任务有独立操作编号，子任务 Begin 包含父操作编号。日志消息在发布线程进入诊断队列，不依赖主界面消息循环；原 Application 文本日志保留不变。

界面线程异常会先写报告再保留标准 .NET 错误对话框；后台未处理异常不吞掉、不自动重启，不增加 PLC 写入/停止命令。未观察 Task 异常会记录但不额外调用 SetObserved。原有 try/catch、相机恢复与通讯状态机仍照原有逻辑处理。

## 证据范围与限制

最后节点是最后观察位置，完成过的任务也会留在列表；不能直接视为卡死根因。Scope ended 只表示作用域退出，不声明检测通过。原生 DLL 崩溃、断电、强制结束、栈溢出或进程严重损坏时，不能保证托管异常报告生成，本功能不产生原生 dump。必要时另收集 Windows 应用程序错误和进程转储。

诊断队列最多 4096 条，磁盘写入在独立后台线程。过载或写盘失败会丢弃并计数；快照记录计数及最后写盘错误，不把丢失伪装成完整记录。正常结束最多等待后台刷盘 1.5 秒，异常终止不保证队列落盘；异常报告独立同步保存最近事件。首次初始化/跨天/分片时清理自身过期文件，约 20 MiB 分片、保留 30 天、总量约 512 MiB（最新分片和当前批次可能超过阈值）；不删除 Application/VisionPro/Project 文件。

导出最近 3 天内的日志，新文件优先，最多 150 文件/100 MiB；单文件最多拷贝末尾 20 MiB，截断和失败记在 README。活动日志只读共享复制，快照另外包含尚未刷盘的最近事件。过大的日志尾部可能从一条记录中间开始。配置最多 200 个 XML，每个不超过 2 MiB；排除 Security；已知密码、密钥、token、connectionstring 字段脱敏。无效 XML 不复制原始内容。导出配置取自导出时，不能证明故障时版本；导出期间配置仍可能变化。

不包含图像、数据库、VPP、账户文件或 DLL/PDB 二进制，只保存 EXE/PDB、VisionPro 引用清单、GoSDK DLL 的 SHA256 身份摘要。日志本身仍可能含产品码、IP、路径等现场信息，分享前检查。需要复现算法时另提供对应图像/VPP；定位行号需保留同一 Build 的源码及 PDB，哈希本身无法还原源码。

## 验证

`Tests/DiagnosticTests.cs` 使用临时目录、合成配置和独立子进程验证 JSONL、脱敏、不修改配置、导出排除项、保留期限、并发队列及实际 AppDomain 未处理异常报告；不加载 Cognex，不连接相机或 PLC。另用当前程序集运行 Help 与手动模拟回归测试。
