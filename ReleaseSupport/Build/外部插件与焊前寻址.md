# 外部插件与焊前寻址

## 部署与启用

主程序首次接入插件框架需要更新 EXE 和根目录的 `Aron.PluginContracts.dll`。以后接口兼容的插件可以单独替换。目标为 .NET Framework 4.7.2、x64、当前 VisionPro 9.6 SR2（程序集 71.2.0.0）。插件清单声明的 API 与 VisionPro 版本必须匹配主程序；不匹配时跳过插件并记录错误。

正常部署目录：

```text
Aron_V2/bin/x64/Debug/
  Visual Inspection.exe
  Aron.PluginContracts.dll                 公共接口，跟随主程序
  Plugins/                                外部插件统一目录，随整个 Debug 复制
    PreWeld/
      Aron.Plugins.PreWeld.dll
      Aron.Plugins.PreWeld.pdb
      plugin.xml
  Project/Config/Plugins/
    Enabled.xml                           本项目的插件选择，缺失时全部关闭
    PreWeld/
      CellFinalizeEvent.xml               启用收集的 Job 与汇总 Pos
      CellInspection.xml                  去重、排序、二维/高度匹配规则
      CellCompensation.xml                各 Job/最终 Cell 序号的 XYZ 补偿
  Data/Plugins/PreWeld/CellData/
    Sessions/                             本轮原始拍照数据和来源
    Summary/                              完整结果与 Replay XML
  Logs/Plugins/PreWeld/                    插件日志
  Logs/Diagnostics/                       公共运行诊断与异常报告
```

默认不启用，不自动导入旧项目参数，也不会创建焊前寻址数据。未启用时只读取 plugin.xml 列出可选模块，不加载 DLL、不创建模块配置/数据目录、不订阅检测处理。不需要的项目可以不拷贝 PreWeld 文件夹；根目录公共接口 DLL 仍需保留。

1. 使用有设置权限的账户，切到 Offline，等待通道和插件后台任务完成。
2. Setting → Setting → External plugins（设置中心 → 外部插件）。插件管理统一保留在设置中心。
3. 勾选 Pre-weld addressing，保存并重启。选择只影响下次启动，不进行生产中热装卸。
4. Tool → External plugins 下出现 Pre-weld setup 与 Cell replay and compensation。这里仅显示插件功能，没有重复的管理入口；没有已加载功能时该菜单隐藏。
5. 在 Pre-weld setup 选择启用、Job、汇总位置，保存。沿用旧版“一套自动汇总事件对应一个 Job/Pos”的模型；Job Control 不会自动克隆这些插件规则。
6. 打开回放与补偿页，设置去重距离、行容差、取点优先级、二维/高度规则、坐标排序方向。保存设置与补偿需要 Offline、配置权限及后台空闲。
7. 自动检测使用同一产品码连续采集各位置。指定汇总位置的所有已启用相机均成功后生成完整 XML。

旧配置如需沿用，关闭程序后手动将原项目的 CellInspection.xml、CellFinalizeEvent.xml、CellCompensation.xml 复制到新的 PreWeld 配置目录，并核对 Job/Pos 与新项目一致；已有文件不要直接覆盖。历史 XML 可通过回放窗口打开，不必迁移到 Project。

## 本次迁移的功能

来源为旧 `V2/Aron_V2_EthernetIP/Aron_V2/CellInspection/CellInspectionService.cs`、`FormCellDataReplay.cs`、`FormCellFinalizeEvent.cs`。保留 Cell/Mark 原始点、二维去重、优先选择 Cam1/较早取点、三角行排序、独立 3D 高度与二维点合并、按 Job 和最终序号补偿、紧凑客户 XML 与完整 Replay XML、地图/表格联动、查询和来源追溯。

- Cell String 支持 `临时序号,X,Y;...` 或 `临时序号,X,Y,Z;...`。旧流程将带 Z 的输出作为独立高度数据，三维数据本身不会替代二维平面点；需要按原规则提供二维点，按需选择 Require height data。
- 优先读取 CellCoordinates、CellCoordinates3D、CellXYZ、CellHeights、CellCoordinate、CellData、CellXY、Cells，再尝试其它可解析的 String 输出。
- Mark 引脚仍为 `Mark`，内容为 `Mark1,X,Y,Z;...`。同一完整汇总内 Mark 名必须唯一。
- Result_Cam=1 且 ToolBlock RunStatus=Accept 才视为成功拍照检测；取像失败、算法异常及最终位置失败重拍不会沿用该相机旧的完成状态。
- 手动触发（含 PLC 交互选项）、本地模拟和 Replay 不收集生产 Cell，不生成生产汇总。自动快照包含产品码、Job/Cam/Pos/Channel、String 输出和已启用存图时的目标图像路径；图像为原 IO 队列异步保存，路径存在不保证图像一定保存成功。
- 同一 Job/产品码的指定位置，所有配置为主/副启用的相机都完成才汇总；跨通道等待，不按相机完成先后猜顺序。没有产品码则跳过并警告。
- 新进程不会自动拼接上次未完成的 Sessions，以免重启后混入旧数据；不同 Job 的数据隔离。失败批次、重复产品码及中途换码需现场按实际节拍验证，插件不替 PLC 创造周期开始/结束信号。
- 已有配置损坏、重复 Mark、要求高度但高度缺失等会停止该插件并记录错误，不更改原检测结果或 PLC 信号。修复后重启恢复插件。

旧界面混合的 Welding Setup、四区焊接、Excel 参考点及 Socket 发送不在本模块内；没有移植网络发送逻辑，也不增加 VPP 固定引脚或改变原 Result_Cam/resultSend 契约。旧窗体主体沿用原英文操作项，入口随主程序语言显示。

## 框架边界

`Aron.PluginContracts` 为固定版本的公共接口，提供只读检测快照、配置/数据/日志目录、目录快照、编辑权限和页面工厂。不给插件相机、CogToolBlock、主窗体、可变缓冲或 PLC transport。焊前寻址 DLL 无 Cognex 或主 EXE 引用，数据适配在主程序中完成，因此不另带 VisionPro/GoSDK DLL。

快照在工具锁内复制 String，完成原检测处理后入队；插件线程串行处理，每个模块最多 256 条/约 32 MiB 待处理输出，单次快照最多 8 MiB。队列溢出/回调异常会停止该模块并报警，避免静默丢数据后继续汇总；不阻塞相机等待插件写盘，不自动改变 Online、Ready、结果或 PLC 连接。错误会出现在主日志/诊断中；软件不将插件异常转成原通道 NG，现场须另外关注插件告警和结果文件。

插件 DLL 与主程序同进程，属于可信代码扩展，不是安全沙箱；不能隔离恶意代码或原生进程崩溃，也不能阻止任意第三方 DLL 自行联网。仅安装经过审核的模块。禁止在插件目录混放 Cognex DLL 或另一份公共接口 DLL；专用托管依赖可放该模块目录，解析限定在请求程序集对应模块，并核对版本。共享依赖身份冲突仍需统一版本或设计独立进程模块，不能承诺任意依赖并存。

更换插件：关闭软件，替换相应子目录中的 DLL/PDB/plugin.xml，保留 Project 配置、Data 与 Logs。接口重大变更需要同时升级主程序与公共接口。缺失或不兼容的已启用插件会显示错误，原自动检测流程仍保持原样，插件不出结果；部署后须核对插件加载状态。

新增模块在独立类库实现 IAronPlugin、声明唯一 ID 和 plugin.xml，使用公共接口初始化、提供页面并处理快照。把模块子目录放入 Plugins，重启后在管理页选择。第一版提供检测完成快照扩展点，其它业务事件需要后续按版本扩展接口，不能绕过接口直接修改主程序内部状态。

## 编译和验证

解决方案增加 Aron.PluginContracts 与 Aron.Plugins.PreWeld 工程。正常编译会将插件 DLL/PDB/清单复制到实际 TargetDir/Plugins/PreWeld；不写 Enabled.xml，不覆盖现场模块参数。Build/Plugins.targets 也适配独立 OutputPath。现有一键 VisionPro 构建会沿用主项目构建目标，插件清单仍固定 9.6 SR2，若主程序选其它版本则拒绝加载，需要另行验证和发布对应兼容清单。

Tests/PluginTests.cs 覆盖默认不加载、重启启用、跨相机汇总、失败重拍、只读快照、模块异常/过载隔离、页面打开和 API 校验；Tests/PreWeldCoreTests.cs 覆盖去重、排序、高度合并、补偿、非法坐标和损坏配置保护。测试均在临时目录使用合成数据，不启动相机或 PLC。原手动模式和菜单测试另做回归；真实 VPP 字符串、现场节拍、标定与机器人使用结果仍需现场验证。
