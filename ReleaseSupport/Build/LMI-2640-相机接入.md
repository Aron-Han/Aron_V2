# Camera 取像绑定（VisionPro 9.6 SR2 x64）

## 保持不变的部分

- 旧 XML 没有 ConnectionMode 时继续使用 Cognex Camera.vpp。普通相机原来的 SN 检查、Load/Save、检测与通讯流程保留。
- SDK 模式只替换图像来源。Inspection.vpp、主副通道执行顺序、PLC 握手、结果输出映射不变。
- 设备配置保存后重启生效，不在生产过程中替换设备或重置通讯。

## 配置 LMI Gocator（含原 2640）

1. 在 GeneralConfig 点击 Add Camera。每次新增都会弹出类型选择：Visionpro 或 SDK；选择 SDK 后目前品牌仅有 LMI，类别自动为 SDK-3D。取消不会新增相机。配置 Position 和主副通道并保存。
2. GeneralConfig 的 Add Camera 前显示当前相机 Mode: Visionpro / SDK，切换 CamN 时同步更新。
3. 打开 Setting → Camera → SDK-3D，选择 Job、Camera、Position。该页不再显示 Channel；生产使用的主副通道仍由 GeneralConfig 配置，不受本次界面精简影响。
4. 填写 Sensor IP 和 Timeout。工具栏 SN 可选；填写后必须匹配 GoSDK 返回的传感器 ID。Provider 在 Add Camera 时确定，页面只在说明中显示品牌，不重复选择；SDK directory 不再显示。
5. Switch Offline，等待当前检测结束后，可使用 Diagnostics 或 Test Capture。测试使用当前输入，不保存参数、不执行算法、不向 PLC 发送结果。
6. 点击上方 Save。重启后应用到生产取像。

绑定按 Job + Camera 保存，同一 Camera 下所有 Position 共用设备。每个 Position 仍使用自己的 Inspection.vpp；SDK 模式不需要 Camera.vpp。不要给同一 Job 的不同 Camera 配相同 IP。不同物理设备可以并发，同一设备的主副通道取像串行，避免串帧。

SDK 页的 Load 重新读取已保存的设备绑定，不读取 Camera.vpp。Visionpro 页恢复原来的完整取像编辑器及 VPP Load/Save，只列出 Visionpro 相机，不再提供混合模式切换条。现有 VPP 不会因为相机分类而删除。

Camera 的右侧二级菜单为 Visionpro、SDK-3D、SDK-2Dline、SDK-2D。后三项为独立分类页面，只有 SDK-3D 当前提供 LMI。没有配置对应类别相机时显示空状态，不能误保存别的类别设备。类别以可选的 SdkCategory 字段保存；旧 LMI 配置缺失该字段时自动归入 SDK-3D，旧普通相机仍默认为 Visionpro。

## GoSDK 部署

- 使用与传感器固件匹配的完整 x64 GoSDK runtime：GoSdkNet.dll、kApiNet.dll（或 Lmi3d.GoSdk.dll、Lmi3d.Zen.dll），以及同版本 GoSdk.dll、kApi.dll 和其依赖。
- 无需逐台相机设置目录。推荐将一套完整、同版本的 x64 runtime 部署在实际运行的 EXE 旁的 LmiSdk 子目录。自动查找顺序为：EXE目录\LmiSdk、Program Files\LMI Technologies\Gocator\GoSdk\bin\win64、Program Files\LMI Technologies\GoSDK\bin\win64。不扫描全盘或自动选择任意最新版本。
- 旧 XML 的 SdkDirectory 高级覆盖仍保留，打开/保存界面不会清空它；有覆盖时只查找指定目录及其常见 GoSDK 子目录，失败会报错，不悄悄换用其他版本。迁移到自动查找时可备份 XML 后清空此字段。Diagnostics 显示实际加载程序集位置。
- 已将本地官方 GO Utilities 6.5.2.5 工具包中的配套 x64 GoSDK 运行库固定到工程 `Aron_V2/LmiSdk`。GoSDK 文件版本 6.5.2.5、kApi 文件版本 10.3.3.22，是同一个工具包自带的配套版本，并非混用。附带其所需的 vcruntime140.dll、ucrtbase.dll；系统 API-set、.NET 4.7.2+ 由 Windows 10/11 提供，不混入工具包内的 x86 转发 DLL。
- 正常 VS 解决方案 Debug 输出（当前映射 x64）为 `Aron_V2/bin/x64/Debug/LmiSdk`；直接编译项目 AnyCPU 的输出为 `Aron_V2/bin/Debug/LmiSdk`。两处都已部署。始终以实际运行的 `Visual Inspection.exe` 所在目录为准，LmiSdk 与它同级。
- 工程通过 `Build/LmiSdk.Runtime.targets` 在每次编译前后校验源文件和输出的 SHA-256，并自动复制完整目录；Release、自定义输出路径、一键分版本构建同样适用。源库保留在工程内，Clean/Rebuild 后会自动恢复到输出，不需要重新从本机软件目录查找。额外混入 DLL 或版本替换会报错，不静默合并。
- 拷贝现场时复制整个实际 Debug 目录，保留 `LmiSdk`、`Project/Config`、`Project/VPP` 等现有目录。LMI 的 GoSDK 不需要另装软件、修改 PATH、注册 DLL 或填写 SDK 路径；仍需正常安装/授权 VisionPro 9.6 SR2，并配置相机 IP、触发/Surface 输出及网络。当前实际 x64 Debug 的 Cam4 旧 SdkDirectory 为空，采用便携库，无需修改该配置。
- 同一进程内所有 LMI 设备使用同一 GoSDK 版本。托管与原生 DLL 不能混用；修改 SDK 版本需要重启。程序不会修改进程全局 DLL 搜索目录，避免干扰 VisionPro/CC24。
- 未配置 SDK 相机的旧项目不加载 GoSDK。相机窗口打开/切换参数不会自动连接设备。
- 启用 GoAccelerator 时填写虚拟传感器地址，不是被加速的物理地址。

LMI Job 必须输出 Uniform Surface，软件触发需相机支持当前 Trigger 设置。Profile/Resampled Profile 不作为 Surface 图像处理。采集超时后走现有相机离线恢复流程。大图转换阶段另允许最多 60 秒完成；界面测试为后台执行。

GoSDK 面向 Gocator 系列，并非 2640 专用 SDK；当前适配器也没有以 2640 型号进行限制。但这不等于已经验证全部 LMI 型号：需确认具体型号支持 Uniform Surface、触发模式、SDK/固件协议兼容性，并实机验证图像与标定。暂不包含 Profile 流处理或其它 LMI 产品系列的专用 SDK。

参考：[LMI 官方 .NET SDK 适用说明](https://support.lmi3d.com/hc/en-us/articles/360032969072-Integrating-the-SDK-within-a-NET-application-C-VB-NET-etc)、[GoSDK 协议兼容说明](https://d3ejaiy6gq5z4s.cloudfront.net/manuals/gocator/gocator-6.1/G2/Content/SoftwareDevelopmentKit/GoSDK.htm)。

## 3D 数据与版本检查

沿用旧版 SDK 转换：有符号高度值加 32768 映射到 16 位 Range；short.MinValue 对应不可见点。根据 GoSDK 的 X/Y/ZResolution 与 Offset 构造 Sensor3D 到 root 的变换，将 CogImage16Range 送入 Inspection.vpp。预览 Bitmap 仅供观察，不替代检测用的原始 Range 数据。

工程继续由现有版本检查目标校验 Cognex 程序集为 71.2.0.0；本次不引入旧工程的 Cognex DLL。9.6 SR2 的 CorePlus/3D 引用使用当前工程现有引用。

## 后续品牌扩展

实现 CameraIntegration.ISdkCameraDevice，在 CameraAcquisition.Providers 注册品牌 ID、显示名、工厂和 Category（SDK-3D / SDK-2Dline / SDK-2D）；新增相机弹窗会自动列出新品牌，SDK 页面沿用新增时确定的 provider。通用设备管理负责按地址隔离、同设备互斥、失败重建、退出释放。品牌新增参数应以可选 XML 字段扩展，保持旧配置默认 Cognex。此阶段只搭建类别页面，LMI 参数沿用现有实现，其它类别具体参数后续再开发。

## 验证边界

后续修复：Comm.dll 的 0x8007045A 已定位为启动进程缺少匹配的 VisionPro bin 搜索路径。在加载前校验并准备进程级路径后，独立预检通过，GoSDK 源文件和绝对路径加载方式不变。详见 [Comm 初始化排查](VisionPro-Comm初始化排查.md)。下文保留修复前的观察记录。

2026-10-23 打包验证：Debug/Release、六个 DLL 的 SHA-256 校验、异地临时目录的 GoSDK 原生/托管初始化、混入/替换 DLL 拒绝测试、模拟通讯回归通过。测试没有创建 GoSystem、连接相机或 PLC。独立 VisionPro 预检在打包前验证程序和打包后 Debug 上均发生 Cognex.VisionPro.Comm.dll 初始化失败（0x8007045A），发生在 GoSDK 加载前；这仍需另外排查，不能据此宣称整机运行或现场验收通过。本次没有修改 VisionPro 安装、PATH、注册表或现有通讯源码。

编译、配置往返、布局与模拟多设备测试不等于实机验收。现场需分别验证：单台取像、两台并发、同设备主副通道、SN 不符、断网恢复、Uniform Surface 数据方向与毫米标定、现有 Inspection.vpp 兼容性以及普通相机与 LMI 混用。

界面验证时曾触发 Cognex.VisionPro.Core.dll 初始化失败（0x8007045A）。现已在编辑器调用入口隔离此异常，SDK 参数页不依赖 Cognex 编辑器初始化，可继续配置；这不等于修复了底层 DLL 初始化问题。真正取像后的 CogImage16Range 转换及算法运行仍依赖正常的 VisionPro 原生运行环境。程序集版本预检通过也不能替代原生初始化与实机取像验证。
